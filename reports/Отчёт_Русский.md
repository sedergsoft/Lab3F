# Отчёт по лабораторной работе № 3 — MiniList<T>

## Цель работы
Реализовать обобщённую коллекцию на основе односвязного списка на C# и обеспечить перебор элементов с помощью интерфейсов `IEnumerable<T>` и `IEnumerator<T>`.

## Теоретические сведения
Односвязный список состоит из узлов. Каждый узел хранит значение и ссылку на следующий узел. Класс `MiniList<T>` хранит ссылки на первый и последний узлы и количество элементов.

## Реализация
- Метод `Append(T item)` добавляет элемент в конец списка и возвращает его индекс, начиная с нуля.
- Свойство `Count` возвращает количество элементов.
- `MiniList<T>` реализует `IEnumerable<T>` — как обобщённый, так и необобщённый интерфейс.
- Вложенный перечислитель явно реализует `IEnumerator<T>): `Current`, `MoveNext()`, `Reset()` и `Dispose()`.
- После достижения конца последовательности `MoveNext()` продолжает возвращать `false`, пока не будет вызван `Reset()`.
- Приложение Windows Forms позволяет создать список, добавить элементы `CheckBox` и отдельно подсчитать визуальные элементы и объекты коллекции.

## Рекомендуемые ручные тесты
1. Запустить приложение и выбрать **Создать список**.
2. Добавить несколько элементов и проверить увеличение счётчика.
3. Выбрать **Перебор кнопок** и проверить количество визуальных элементов.
4. Выбрать **Перебор объектов** и проверить количество элементов коллекции.
5. Создать новый список и убедиться, что он пуст.
6. Попробовать добавить элемент до создания списка и проверить информационное сообщение.
7. Проверить перечисление пустого списка, списка с одним и несколькими элементами. После первого `MoveNext()`, вернувшего `false`, последующие вызовы должны возвращать `false` до `Reset()`.

## Вывод
Реализованы обобщённый односвязный список и явный перечислитель, совместимый с контрактами .NET. Графический интерфейс демонстрирует связь между элементами управления и объектами коллекции.

## Статус проверки
Код проверен статически, однако сборку и запуск необходимо подтвердить через GitHub Actions в Windows с .NET 8. Лабораторную работу нельзя считать полностью проверенной до успешного завершения workflow и сверки с официальным заданием.
